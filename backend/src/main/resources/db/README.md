# DB 스키마 및 backend 인계 계약

## 정본과 실행 소유권

- `../schema.sql`은 승인 경계를 반영한 현재 스키마 정본이다.
- `migration/V1__foundation.sql`은 최초 정본의 **바이트 동일 SQL 복제본**이다.
  psql include 또는 두 번째 독립 스키마를 사용하지 않는다.
- backend 설정 담당자는 `spring.sql.init.mode=never`와 `spring.flyway.enabled=true`를 적용한다.
- 운영 Flyway 위치는 `classpath:db/migration`만 사용한다.
- local 프로필에서만 `classpath:db/migration,classpath:db/local`을 사용한다.
  `db/**` 전체 스캔으로 운영에 로컬 시드를 포함하지 않는다.
- V1 적용 후에는 V1을 수정하지 않는다. 새 migration과 schema.sql 현재 정본을 함께 갱신한다.
  최초 생성 상태에서만 schema.sql과 V1의 바이트 동일성을 유지한다.
- `CREATE TABLE/INDEX IF NOT EXISTS`는 동일 DDL 재실행을 허용하지만 기존 오염 스키마를
  자동 복구하지는 않는다. Flyway 이력·checksum 검증을 우회하지 않는다.

## 정확한 타입과 nullability

물리 컬럼의 최종 근거는 schema.sql이다. 아래 필드 외 추가 컬럼을 mapper에서 가정하지 않는다.

- 모든 테이블: `created_at`, `updated_at` = `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- 숫자 PK = `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
  INSERT 시 PK를 생략하고 PostgreSQL `RETURNING` 또는 MyBatis 생성 키로 받는다.
- 예외 PK: `role.role_code TEXT PRIMARY KEY`, `session.session_id TEXT PRIMARY KEY`.
  세션 키는 예측 불가능한 서버 생성 문자열이며 숫자 identity로 바꾸지 않는다.
- 문자열은 길이를 발명하지 않고 `TEXT`이다.
- PK와 메타 일시 외 모든 컬럼은 NULL 허용이다. API 응답의 required 키를 DB NOT NULL로 승격하지 않는다.
- 날짜는 `DATE`, 정렬은 `INTEGER`, 접근 허용은 `BOOLEAN`, 추가속성은 `JSONB`이다.

아래 목록은 공통 메타 2개를 제외한 전체 컬럼이다.

| 테이블 | PK | 나머지 정확한 컬럼/타입 |

| korus_personnel_snapshot | personnel_id BIGINT | employee_number TEXT; person_name TEXT; organization_id BIGINT; job_grade TEXT; employment_status TEXT; retirement_date DATE; last_synced_at TIMESTAMPTZ; use_status TEXT |

Java/MyBatis 매핑은 nullable `Long`, `Integer`, `Boolean`, `String`, `LocalDate`,
`OffsetDateTime` 등 참조 타입을 사용한다. JSONB는 JSON 직렬화와 JDBC OTHER 또는
명시 `CAST(... AS JSONB)` 처리를 구현하고 JSON 문자열을 DTO 객체로 역직렬화한다.
맵 응답에서 quoted alias를 사용하고 wire DTO의 snake_case 이름과 구별한다.
`updated_at`은 UPDATE마다 애플리케이션이 서버 일시로 갱신한다. 자동 UPDATE 트리거는 없다.

## 키·참조·인덱스

- 유일성: 각 PK와 `user_account.login_id`의 기술 UK만 존재한다.
- `role.role_code`의 R01..R09 CHECK는 원문 확정 역할 코드 계약이다.
  상태 필드의 미승인 enum과 다르다.
- 모든 명시 관계 FK는 원문 대상의 PK를 참조하며 기본 NO ACTION이다.
  CASCADE 삭제/갱신, 관계 대상 XOR 및 업무 중복 UK는 없다.
- 조직/메뉴/상세코드의 부모 FK는 자기 테이블 PK를 참조한다.
- 조직코드·교번·화면ID·그룹ID·코드값·부여쌍·권한 대상쌍의 업무 유일성은 발명하지 않았다.
  따라서 이 필드를 ON CONFLICT 대상으로 사용할 수 없다.
- 승인된 설계 인덱스는 V1에 모두 선언했다. user_role.approver_id와 모든 검색·관계 인덱스는
  data-model.md Table Contract와 동일하다. menu_permission은 메뉴+각 대상 복합 인덱스다.

## 승인 게이트와 인증 인계

- OQ-001: organization과 인사·보직 스냅샷은 관리 API 읽기 전용이다.
  로컬 overlay 및 `organization_relationship_history` 테이블은 만들지 않았다.
  REQ-010 요구를 삭제한 것이 아니며 승인 후 별도 migration으로 관계·이력 경계를 구현한다.
- OQ-002: 메타 일시가 전후값·처리자·사유 추적을 충족한다고 주장하지 않는다.
  승인되지 않은 audit 테이블/트리거를 생성하지 않았다.
- 상태/사용여부/재직상태/부여 구분은 `TEXT NULL`, 기본값과 CHECK enum이 없다.
  advisory AGENTS의 허용값 COMMENT 형식은 미승인 값 발명 금지와 충돌하므로
  실제 컬럼 COMMENT에 OQ 승인 대기를 기록했다.
- 초기 admin 계정 및 R09 부여의 NULL use_status/assignment_status는 비활성 또는 회수가 아니다.
  로그인·역할 조회가 `status = 'ACTIVE'`, `use_status = 'Y'` 같은 발명한 값으로 시드를 배제하면 안 된다.
  NULL 승인자/기간/부여 구분을 자동 승인·수동 부여 또는 만료로 추정하지 않는다.
- 기간 효력·회수 표현·사용중지 세션 차단·세션 수명은 승인 대기다.
  존재하는 초기 역할 매핑과 명시 menu_permission.access_allowed를 사용하되
  미승인 충돌 합성 또는 R09 전역 bypass를 도입하지 않는다.
- 세션은 로그인 시 생성한다. 세션 키와 password_hash를 JSON 응답이나 로그에 노출하지 않는다.
  로그아웃 후 인증 종료 방법은 backend 소유이며 미승인 상태 코드를 DB 시드하지 않는다.

## local fixture

`local/V900__local_seed.sql`은 DB에만 저장하는 합성 fixture이며 운영 데이터가 아니다.

- R01..R09 원문 역할명과 목적; 기준·범위·상태는 미승인 NULL.
- admin 계정은 로컬 Python/libcrypt BCrypt 계산값만 저장한다.
  Spring `BCryptPasswordEncoder`로 검증하며 delegating encoder 사용 시 저장 형식 처리를 별도 정렬한다.
- 합성 조직 1건, 교직원 1건 및 보직 1건. 관리자 계정은 해당 교직원에 연결된다.
- 시스템 관리 대메뉴 1개, 중메뉴 4개, UI 정본의 화면ID·route를 가진 leaf 9개.
- R09 명시 허용은 root·middle·leaf 전체 14개 메뉴에 삽입한다. /login 메뉴 없음.
- 합성 코드그룹/상세코드 1건과 JSONB 속성; 미승인 상태·기간은 NULL.
- identity 값을 직접 지정하지 않는다. 재실행 시 기존 관리값·비밀번호·권한을 덮어쓰지 않는다.
  이 시드는 Flyway 단일 실행 전제이며 동시 fixture 로더를 위한 업무 UK는 발명하지 않는다.

## 검증 범위

이 작업의 실행 소유자는 runner다. 빌드·테스트·컨테이너·네트워크 및 DB migration 실행은 수행하지 않았다.
필드·타입·FK/인덱스 선언·복제본 동일성·UI route 정렬은 로컬 정적 비교 대상이다.
실제 PostgreSQL 16 migration, BCrypt Java 로그인, mapper materialization, 인증된 9개 조회,
재시작 영속성은 **awaiting runner verification**이다.
